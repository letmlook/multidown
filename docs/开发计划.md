## 四、关键技术设计

### 4.1 动态分段（M2.2）

```
未完成区间: Vec<(start, end)>          // Mutex<Vec<Range>>
worker loop:
  1. 取段: 取最大段 seg；若 seg.len > 2*MIN_CHUNK → 对半切，本 worker 拿前半，后半放回
  2. 下载该段，写入 offset
  3. 段完成 → 回到 1；全部完成 → 任务完成
暂停: worker 记录当前段的 [done_start, cur) 放回区间集合
```
- `MIN_CHUNK` 建议 1MiB；段数无上限（替代静态 N 段）
- `settings.max_connections_per_task` 变为"初始 worker 数"
- 现有持久化的 pending segments 结构可直接复用为区间集合

### 4.2 令牌桶限速（M2.3 / M3.1）

```
struct TokenBucket { rate_bps: AtomicU64, tokens: Mutex<f64>, last: Mutex<Instant> }
async fn acquire(&self, want: usize) -> usize   // 返回实际可读字节数
```
- 读流循环：`let n = bucket.acquire(8192).await; read(n)`
- 全局桶 + 每任务桶串联；Schedule 的 `SpeedLimit` 规则直接改 `rate_bps`
- 零限速值 = 不限速（桶直通）

### 4.3 定时调度（M3.1）

- `setup` 中：`tokio::spawn(async move { loop { sleep(30s); manager.tick(Local::now()).await → 处理事件 } })`
- 事件类型已有：`StartTask / PauseAll / ResumeAll / SpeedLimit`
- 注意与暂停状态机互斥：ScheduledPause 不覆盖用户手动暂停

### 4.4 规则/代理的统一应用点（M3.2 / M3.3）

- 所有任务创建入口（手动两个 command + 扩展 TCP 消息 + 批量编排）收敛到一个内部函数 `ingest_url()`，规则改写目录、代理匹配改写 NetworkOptions、查重都在这一处，避免四处散落。

## 五、风险与依赖

| 风险 | 缓解 |
|------|------|
| 动态分段重构触碰核心下载路径，回归风险最高 | M2.1 先补测试锁定行为；保留静态分段作 fallback 开关 |

| Windows/Linux 行为本机无法验证 | 依赖 CI 三平台构建 + 发布前远程验证 |
| MV3 service worker 休眠影响 native messaging | 现有实现已在用，保持心跳/按需唤醒模式 |
