# 磁力链接 / 种子文件下载 — 设计与实施方案

> 审计基线：当前工作区（`src-tauri/src` 约 7.2k 行 Rust，`src/` 约 1k 行 TS）
> 结论先行：**技术上完全可行**。建议引入 `librqbit` 9.0.1 作为 BitTorrent 引擎，把任务模型从「HTTP 分段任务」
> 抽象成「协议化任务」，按 6 个里程碑落地。核心难点不在 BT 协议本身（库已经解决），而在
> **现有引擎到处硬编码了「任务 = 一个 URL + 一个文件 + 一段线性字节区间」这个假设**。

## 一、结论速览（TL;DR）

| 问题 | 结论 |
|------|------|
| 参考对象 | **Motrix Next（现名 Rayburst）** 是同赛道的 Tauri 2 下载器（5.1k★），已完整实现磁力/种子，本方案大量借鉴其做法，见 §3.4 |
| 两条技术路线 | ① **内嵌 `librqbit` 9.0.1**（纯 Rust，无外部二进制，推荐）；② **aria2 sidecar**（Rayburst 路线，BT 成熟但要分发 per-platform 二进制） |
| 改动量级 | 后端约 1200~1800 行新增/改动，前端约 600~900 行；**两条路线的任务模型/UI/协议处理器工作量几乎相同**，差异只在引擎适配层 |
| 最大风险 | **MSRV 必须 ≥ 1.88**（`librqbit` 9.x 是 edition 2024 且用了 Rust 1.88 才稳定的 `let` chains）；项目现已把 `rust-version` 更新为 `1.88` |
| **功能缺口（务必先确认）** | librqbit **不支持 BEP 19 web seed、不支持 MSE/PE 连接加密、没有真正的顺序下载**。加密缺失会影响部分私有 tracker |
| 实测代价 | 二进制 **+6.33 MiB**（macOS arm64，`lto=fat + panic=abort + strip` 实测）；`Cargo.lock` 595 → **703** 个包（净 +108），引入 `reqwest` 0.12+0.13、`base64` 0.21/0.22/0.23、`thiserror` 1+2、`rand` 0.9+0.10 等重复版本 |
| 最佳抄写对象 | **librqbit 作者自己写了一个 Tauri 2 + librqbit 桌面应用**：`ikatson/rqbit` 的 `desktop/src-tauri/`。它的 `Api` facade 已封装好增删改查，`ApiError` 实现了 `Serialize`，可直接作为 Tauri command 的错误类型 —— 架构照抄即可 |
| 架构关键 | 把 `Task` 协议化（`TaskKind::Http / TaskKind::Torrent`），HTTP 路径维持现状，Torrent 走独立 runner |
| 多文件怎么处理 | 一个种子 = 一个任务，`save_path` 指向种子根目录，任务详情里展开文件列表（对齐 IDM/迅雷的用法） |
| 元数据从哪来 | 用 `AddTorrentOptions { list_only: true }` 先解析元数据拿文件列表，同时拿到 `torrent_bytes` 落盘缓存 |
| 进度怎么接 | 每任务一个 500ms stats 轮询器，写入现有 `Task.downloaded` + 复用 `download-progress` 事件 |
| 限速怎么接 | `session.ratelimits.set_download_bps()`（同步方法），与现有全局 TokenBucket 并存 |
| 代理怎么接 | **只支持 SOCKS5**，且必须同时关闭 DHT/LSD，否则会绕过代理泄漏真实 IP |
| 顺带发现 | `tauri-plugin-single-instance` 未开 `deep-link` feature，Windows/Linux 上"运行中点击 `multidown://`"目前是**失效**的 |

### 已知欠账 / 注意事项

1. **占位任务的文件名不随后续元数据更新**：以磁力 `dn`（或 hash 前缀）为准，
   与 qBittorrent 的展示一致；`filename` 可变化会牵连 `save_path` 语义，收益比不划算。
2. **`TaskInfo.seeds` 恒为 `null`**：librqbit 的聚合 stats 不区分"做种方"。如实返回 null 而非误报 0。
3. **运行中改选文件后，前端以任务快照的 `files[].selected` 为准**（引擎侧是权威来源，
   librqbit 会话会一并持久化），`PersistedTask.torrent.selected_files` 只是首次添加的提示值。
4. **BT 设置里"监听端口 / DHT / LSD / 代理"在会话已创建后需重启应用生效**
   （限速与做种策略实时生效）；UI 已注明。
5. **做种策略的 ratio/time 在应用退出后不延续**：重启后完成任务即停在 Completed 状态。
6. `create_torrent_download` 会**拒绝非种子输入**（http 链接请走 `create_download`）。
7. macOS 上磁力默认程序要求 `magnet` scheme 已在 Info.plist 声明（`tauri.macos.conf.json`），
   且必须用 `tauri build` 产物测试（`tauri dev` 收不到磁力链接）。

### 尚未验证

## 二、现状：为什么现在的引擎吃不下磁力链接

### 2.1 引擎里对 HTTP 的隐式假设（逐处核对）

| 位置 | 现有假设 | 对 BT 的影响 |
|------|----------|--------------|
| `engine/types.rs:34` `CreateTaskInput` | 任务输入 = `url` + `save_dir` + `filename` | 磁力链接没有"文件名/单文件"语义 |
| `engine/task.rs:12` `Task` | 单 URL、单 `save_path`、`pending_segments: VecDeque<(u64,u64)>` | BT 的分片调度由 peer 协议驱动，不是线性区间 |
| `engine/scheduler.rs:235` `create_task_internal` | 必调 `probe()`（HTTP HEAD/Range）才能建任务 | 磁力链接不能 HEAD |
| `engine/scheduler.rs:383` `start_download` | `n_workers` 个 worker + `run_worker` 拉 Range | BT 需要的是会话内多 peer，不是我们开 N 个 HTTP 连接 |
| `engine/writer.rs:11` `run_file_writer` | 按 offset 写**单个**文件 | BT 是多文件 + 分片校验 + 续传位图 |
| `engine/persistence.rs:10` `PersistedTask` | 靠 `pending_segments` 表达续传 | BT 续传状态在 bitfield/fastresume 里 |
| `network/client.rs:111` `probe_with_client` | 只有 HTTP 语义 | 需要新增协议嗅探 |
| `lib.rs:1277` `parse_scheme_url` | 只放行 `http://` / `https://` | `magnet:` 被丢弃 |
| `lib.rs:2304` 本地 TCP 桥 `"download"` 分支 | 只放行 `http://` / `https://` | 扩展捕获的磁力链接被拒 |
| `lib.rs:1874` `import_tasks` 文本导入 | 只放行 `http://` / `https://` | 导入磁力列表失败 |
| `integration/native-host/src/main.rs:143` | 只放行 `http://` / `https://` | Native Host 直接拒绝 |
| `src/App.tsx:137` 剪贴板监听 `isHttpUrl(url)` | 只认 http | 复制磁力链接无反应 |
| `src/types/download.ts:9` `TaskInfo` | 无 `kind`、无上传速度、无 peers/seeds | UI 无法展示 BT 信息 |
| `engine/scheduler.rs:66` `speed_limit: TokenBucket` | 只被 HTTP worker 消费 | BT 速度不受全局限速约束 |
| `integration/extension/manifest.json` | 无磁力相关处理 | 右键菜单不认 `magnet:` |

### 2.2 四条"下载入口"都需要打通

磁力链接可能从四个地方进来，四个地方目前都写死了 http：

| 入口 | 文件 | 现状 | 需要 |
|------|------|------|------|
| ① 手动新建任务 | `src/components/AddTask.tsx:130`（`type="url"` 输入框） | 只能填 http | 识别 `magnet:`、支持"打开种子文件…"、支持拖拽 `.torrent` |
| ② 剪贴板监听 | `src/App.tsx:137` `isHttpUrl()` | 只认 http | 加 `isMagnetUrl()` |
| ③ URL Scheme | `lib.rs:1277` + `tauri.conf.json` `deep-link.schemes` | 只有 `multidown` | 加 `magnet` scheme 并处理裸 `magnet:` 参数 |
| ④ 浏览器扩展 | `native-host/src/main.rs:143` → `lib.rs:2304` | 只放行 http | 白名单加 `magnet:`（扩展还需加右键菜单项） |

## 三、技术选型

### 3.1 候选对比

| 方案 | 版本 / 状态 | 磁力 | 种子文件 | DHT | uTP | 文件选择 | 限速 | 嵌入式 | 结论 |
|------|-------------|------|----------|-----|-----|----------|------|--------|------|
| **librqbit** | 9.0.1 / 2026-08-20 / Apache-2.0 | ✅ | ✅ | ✅ | ✅ | ✅ | ✅ | ✅ 纯 Rust lib | **选用** |
| cratetorrent | 0.1.0（2020-12-22，最后提交 2021-12-19） | 部分 | ✅ | ❌ | ❌ | ❌ | 部分 | ✅ | 弃：**硬依赖 tokio 0.2**（本项目是 tokio 1）且 **仅支持 Linux** |
| rust-torrent / tokio-torrent | **crates.io 上不存在** | ❌ | 部分 | ❌ | ❌ | ❌ | ❌ | ✅ | 弃 |
| bip-rs / `bittorrent` | 0.2.0（2017，最后提交 2018-07-03） | ❌ | 仅解析 | 原语 | ❌ | ❌ | ❌ | ✅ | 弃：不是客户端，只是一堆协议原语 |
| irontide | 1.7.0（2026-07-18，几乎无维护） | ✅ | ✅ | ✅ | ? | ? | ? | ✅ | 弃：**GPL-3.0，与 MIT 项目不兼容** |
| aria2c / aria2-next 外部进程 | 活跃（Rayburst 用的 fork，**GPL-2.0**） | ✅ | ✅ | ✅ | ❌ 仅 TCP | ✅ | ✅ | ❌ 需分发二进制 | **路线②**，见 3.3 / 3.4 |
| transmission 外部进程 | 活跃（**GPL-2.0+**） | ✅ | ✅ | ✅ | ✅ | ✅ | ✅ | ❌ 需分发二进制 | 同上，体积/依赖更重 |
| 自研 BT | — | — | — | — | — | — | — | — | 工作量数倍于本项目总量，不可行 |

> **许可证是路线②的一项真实成本**：aria2 与 transmission 都是 GPL。把它们作为二进制随 MIT 安装包分发
> 会带来 GPL 合规义务（随包提供对应源码/许可证声明）。Rayburst 自身是 MIT 却捆了 aria2-next，
> 这是一个需要确认的暴露点。librqbit 的 Apache-2.0 没有这个问题。

### 3.2 选型结论：librqbit 9.0.1

**实测依据**（直接下载 crates.io 的 `.crate` 源码逐条核对，非文档推测）：

- 版本 / 许可：`9.0.1`，发布于 `2026-08-20`，仓库最后提交 `2026-09-24`，`Apache-2.0`（与项目 MIT 兼容，
  保留 NOTICE 即可）。其全部同级 crate（`-core`/`-dht`/`-utp`/`-tracker-comms` 等）同为 Apache-2.0。
- **MSRV 实际是 ~1.88，不是 1.85**：`edition = "2024"`（⇒ ≥1.85）**加上**使用了 `let` chains
  （`&& let`，如 `src/session.rs:849`），而 `let` chains 到 **Rust 1.88.0** 才稳定；
  依赖 `rand 0.10` 也声明了 1.85。librqbit **没有声明 `rust-version`**，所以 Cargo 的 MSRV 感知解析器
  拦不住它——**表现是编译期报错，而不是依赖解析报错**，这一点容易被误判为"环境问题"。
- `src-tauri/Cargo.toml` 已把原先失效的 `rust-version = "1.70"` 修正为 `1.88`；锁定的
  `tauri 2.10.2` 自身也要求 ≥ 1.77.2。
- 默认 feature 为 `["default-tls", "http-api-client"]`；**`http-api`（axum 内置 HTTP 服务）不在默认里**——
  嵌入后不会悄悄开一个 HTTP 端口（那是需要你自己 `HttpApi::new(...).make_http_api_and_run(...)` 才会起的东西）。
- 能力矩阵（源码级确认）：magnet（自有解析器）、`.torrent` 字节流、DHT、PEX(BEP11)、LSD、
  uTP + TCP、UDP tracker + HTTPS tracker、BEP 9 元数据交换、BEP 53 `so=`、`only_files` 选文件、
  `list_only` 只列不建、运行时限速、会话持久化 + fastresume、IPv6 dualstack、UPnP、
  按文件流式读取 `ManagedTorrent::stream(file_id)`。
- **三个能力缺口（比"体积/MSRV"更值得先确认）**：

  | 缺口 | 影响 | 变通 |
  |------|------|------|
  | **无 BEP 19 web seed**（源码里 `url-list` 出现 0 次） | 依赖 HTTP 种子源的大包下载会明显变慢 | 无解；若目标资源重度依赖 web seed，只能换 aria2 |
  | **无 MSE/PE 连接加密**（`grep -i encrypt` 在 `src/` 下 **0 命中**） | **部分私有 tracker 强制要求加密**，会连不上或直接被拒 | 无解；PT 用户必须换引擎 |
  | 无真正"顺序下载"（0 命中 `sequential`） | 边下边播体验不如专业客户端 | 用 `handle.stream(file_id)` 做按文件流式读取近似 |

- 其余限制：**magnet 只支持 v1 infohash**（`as_id20()` 对纯 v2 报
  `magnet link didn't contain a BTv1 infohash`）；**做种控制只有编译期 `disable-upload`**，
  没有 seed-ratio / seed-time，需要我们自己轮询 + `pause` 实现（见 §4.8）。
- **`Session::new*` 会无条件绑定 socket**：DHT 的 UDP 端口、BT 的 TCP/uTP 监听、LSD 组播。
  → 首次启动会触发三平台防火墙弹窗，必须提供"显式端口 + 关闭 LSD"的设置项（见 §4.6）。
- 运行时要：`BlockingSpawner::new()` 内部调用 `tokio::runtime::Handle::current()`
  （`src/spawn_utils.rs:17`，由 `src/session.rs:684` 调用），**Session 必须在 tokio 运行时的上下文里创建**。
  它显式适配运行时风格（`CurrentThread => allow_block_in_place = false`，`MultiThread => true`），
  多线程运行时可用；`Session` 是 `Send + Sync` 且返回 `Arc<Session>`（注意 `add_torrent` 接收
  `self: &Arc<Self>`，所以必须持有 `Arc` 而不是 `&Session`）。另外应设置
  `SessionOptions.runtime_worker_threads`，避免阻塞任务饿死运行时。

**依赖影响（实测，非估算）**：

| 指标 | 数值 |
|------|------|
| 二进制体积 | 空程序 341,280 B → 加 librqbit **6,635,920 B ≈ 6.33 MiB**（macOS arm64，`lto="fat"` + `codegen-units=1` + `panic="abort"` + `strip=true`） |
| `Cargo.lock` 包数 | 595 → **703**（净 **+108**，371 条新增或改版） |
| 引入的重复版本 | `reqwest` 0.12.28 + **0.13.5**、`base64` 0.21/0.22/**0.23**、`thiserror` 1 + **2**、`rand` 0.9 + **0.10**、`rand_core` 0.6/0.9/0.10、6 个 `windows-sys` 版本 |
| 新增的关键依赖 | nix 0.30、governor 0.10、memmap2、intervaltree、dashmap、tokio-socks… |

**🏆 最佳参考实现：librqbit 作者自己写的 Tauri 2 应用**

`ikatson/rqbit` 仓库里有一个 `desktop/src-tauri/`，**就是 Tauri 2 + librqbit 的桌面应用**，
作者为这个场景专门写的。应当**直接照抄它的架构**，而不是从零设计：

```rust

```

它用 `Api` facade 把增删改查全部封装好了，且 **`ApiError` 实现了 `Serialize`，可以直接作为
Tauri command 的错误类型**：

| 我们的需求 | 现成 API |
|-----------|----------|
| 任务列表（带进度） | `api_torrent_list_ext(ApiTorrentListOpts { with_stats: true })` |
| 加磁力 / 加种子字节 | `api_add_torrent(AddTorrent::Url(..) / AddTorrent::TorrentFileBytes(..), opts)` |
| 任务详情（含文件列表） | `api_torrent_details(id)` → `TorrentDetailsResponseFile { name, components, length, **included**, attributes }` |
| 统计 | `api_stats_v1(id)` / `ManagedTorrent::stats()` |
| 暂停 / 继续 | `api_torrent_action_pause(id)` / `api_torrent_action_start(id)` |
| 删除（含文件）/ 仅移除记录 | `api_torrent_action_delete(id)` / `api_torrent_action_forget(id)` |
| **改选文件** | `api_torrent_action_update_only_files(id, &HashSet<usize>)` |
| 关停 | `api.session().stop().await` |

其中 **`TorrentDetailsResponseFile.included: bool` 就是文件选择状态**
（源码 `included = only_files.map(|o| o.contains(&idx)).unwrap_or(true)`），前端复选框直接绑它即可，
不必自己维护一份选择模型。另外 `TorrentIdOrHash::{Id(usize), Hash(Id20)}` 实现了
`Serialize`/`Deserialize`，前端可以用 id 或 infohash 定位任务。

解析磁力链接时若想在**建任务之前**先给用户看确认框，可以只用 librqbit 自带的解析器
（`librqbit::Magnet::parse`，`as_id20()` / `name` / `trackers` / `get_select_only()`），
不必额外引包；若想有更独立的解析器可选 `magnet-url` 3.0.0（MIT，零运行时依赖）。

### 3.3 第二条路线：aria2 sidecar 进程

> 这条路线的完整现实样本见 §3.4（Motrix Next / Rayburst）。它不是"没人用过的降级方案"，
> 而是一个已被 5.1k★ 项目验证的成熟选择。

若评估后不愿承担 `librqbit` 的体积与 MSRV 代价，可以改为**捆绑 aria2c（或 aria2-next fork）**：
以 `externalBin` 作为 sidecar 启动，开 `--enable-rpc`，用 JSON-RPC 驱动，BT/HTTP 都交给它。优点是：

- BT 栈是十余年实战的 C++ 实现（DHT/PEX/LPD/加密/选文件/元数据缓存/web seed 全都有）；
- 不改动本项目现有 HTTP 引擎的任何一行（只做 BT 分支，风险可控）；
- 顺手可以加 ED2K / HLS / DASH / SFTP（Rayburst 就是这么扩展的）。

缺点是：

- 要给 Windows/macOS/Linux × x64/ARM64 各分发一个第三方二进制（~5MB/平台），
  要么自己用 CMake 构建 aria2-next，要么依赖上游发布的产物，打包与许可证合规成本高；
- **无法提供便携版**（sidecar 必须与主程序同目录，Tauri sidecar 模型的固有限制）；
- 需要额外写进程看护（崩溃重启、端口冲突、僵尸进程、动态端口与密钥）；
- 任务模型出现"两套真相"（HTTP 走自己的引擎，BT 走 aria2），需要统一的适配层。

**结论**：把它作为**路线②**保留，并用 §4.2 的 `TorrentBackend` trait 把引擎差异隔离，
这样"先上 librqbit，不行再换 sidecar"的成本被压到最低。

### 3.4 参考实现：Motrix Next（现名 Rayburst）

Motrix Next 是与本项目几乎同构的参考对象——**同样是 Tauri 2 桌面下载器，同样支持磁力/种子**，
而且它的作者把"Magnet Next 全功能"完整做出来了（5.1k★，Windows 安装包 16.3MB / macOS 20.9MB）。
项目后来改名为 **Rayburst**，源码可读。本节结论均来自直接阅读其源码。

**它的技术栈与引擎选择**

| 层 | 选择 |
|----|------|
| 运行时 | Tauri 2 + Rust |
| 前端 | Vue 3 Composition API + Pinia + Naive UI（本项目是 React，不影响借鉴） |
| **下载引擎** | **`aria2-next` sidecar 进程**（作者自己维护的 aria2 fork，`AnInsomniacy/aria2-next`），通过 Tauri `externalBin` 打包 |
| 引擎通信 | Rust 侧自研 **JSON-RPC 客户端**（`src-tauri/src/aria2/rpc.rs`），`reqwest` + `.no_proxy()` POST `http://127.0.0.1:{port}/jsonrpc`，`token:` 鉴权 |
| 任务历史 | 独立 **SQLite**（`src-tauri/src/database/`），与引擎会话状态分开 |

另外从 `engine/config.rs` 读到两条**重要的默认策略**：

- **默认不做种**：强制 `seed-ratio=0`，只有开启"保种"时才写入 `seed-time`（第 211 行 `insert_option(&mut options, "seed-ratio", "0")`）。
- **SOCKS 代理被显式跳过**：`all-proxy` 若以 `socks` 开头会记 warning 并丢弃（第 196 行）——也就是说
  aria2 路线下 BT 的代理支持同样是个坑，**不是"换了 aria2 就自动解决"**。

**它怎么处理磁力链接的"元数据 → 选文件"**（这正是本方案 §4.3 的流程）

- `TaskInput::Torrent(base64)`、`aria2_inspect_torrent`（**只解析元数据、不建任务**、不写引擎状态）
- 任务的 BT 信息里带 `file_selection_state` 字段，取值含 `awaiting-selection`
- `tasks/mod.rs:226` 的"恢复全部"逻辑专门写了一条：
  **"只恢复那些不需要等待用户选文件的暂停任务"**——即元数据已解析但用户还没勾选文件的磁力任务保持 paused
- 文件模型是 `Aria2File { path, selected: "true"/"false", uris, ... }`，配套 `content_paths(files, selected_only)`
  与磁盘可用性监控（`tasks/files.rs`）

**它的三平台协议处理器注册（这块我的原始方案判断有误，已在本方案 §4.9 修正）**

| 平台 | 做法（源码位置） |
|------|------------------|
| Windows | 不用 `tauri-plugin-deep-link` 的 `register()`（那会直接抢占默认值）。改为在 NSIS 里注册 **候选应用**：`Software\RegisteredApplications` + `Software\{BUNDLEID}\Capabilities\{URLAssociations,FileAssociations}` + ProgID `Software\Classes\{BUNDLEID}.magnet`，然后用 `AssocQueryStringW` 查询当前默认、把用户引导到 `ms-settings:defaultapps?registeredAppUser=...` 让用户自己选。卸载时**只删除仍然指向本程序安装路径的键**（`nsis/hooks.nsh`） |
| macOS | **可以在运行时改默认程序**：`LSSetDefaultHandlerForURLScheme("magnet", bundle_id)`，`.torrent` 走 `LSSetDefaultRoleHandlerForContentType(UTType→public.filename-extension:torrent)`；查询用 `NSWorkspace.URLForApplicationToOpenURL` / `LSCopyDefaultRoleHandlerForContentType`；`-128` 表示用户取消。`commands/protocol/macos.rs` |
| Linux | 用 **GIO**（`gio::AppInfo` / `DesktopAppInfo`）而不是 shell 调 `xdg-mime`：写 `.desktop`（`MimeType=application/x-bittorrent;x-scheme-handler/magnet;`）→ 用 GLib 解析 `Exec` 字段**校验这个 desktop 条目确实属于自己**→ `set_default`。还带 `diagnostics()` 输出 `XDG_CURRENT_DESKTOP` 等排障信息。`commands/protocol/linux.rs`（436 行） |

**外部输入（argv / 深链 / 文件关联）的统一处理**（`services/deep_link.rs`）

```rust
// 只放行真正的下载输入，忽略 CLI 开关
lower.contains("://") || lower.starts_with("magnet:") || lower.ends_with(".torrent")
// 并额外支持 file:///Users/xx/a.torrent（macOS 的 RunEvent::Opened 给的是 file URL）
```

它还实现了"**前端未就绪时先入队、就绪后 drain**"的待处理队列——因为它在轻量模式下会**销毁 WebView**
（Rust 侧继续跑引擎）。本项目不销毁 WebView，所以不需要这么复杂，但"深链可能在监听器注册前到达"
这个问题同样存在，值得保留一个简化版队列。

**两条路线在本项目上的对比**

| 维度 | ① 内嵌 librqbit | ② aria2 sidecar（Rayburst 路线） |
|------|-----------------|----------------------------------|
| BT 成熟度 | 好（rqbit 内核，DHT/PEX/uTP/加密） | **很好**（aria2 十余年实战，含 web seed、ED2K、HLS 等） |
| 外部二进制 | **无** | **有**，6 个平台各一个（Windows/macOS/Linux × x64/ARM64） |
| 安装包体积 | +6~12MB（Rust 静态链接进主程序） | +5~8MB（独立 sidecar 文件） |
| 便携版 | 不受影响 | **无法做便携版**——sidecar 必须与主程序同目录，Rayburst 官方 FAQ 明确说明因此放弃了 portable |
| MSRV | 需要 ≥1.88（edition 2024 + let chains） | 不受 librqbit 影响，但仍受 Tauri 的 ≥1.77.2 约束 |
| 依赖冲突 | 引入 reqwest 0.13 / base64 0.23 / thiserror 2（双版本共存） | 无 Rust 依赖冲突 |
| 需要写的适配层 | ~600 行（会话管理 + stats 轮询 + 状态机） | ~800 行（RPC 客户端 + sidecar 看护 + 运行时配置 + 端口/密钥管理） |
| 额外收益 | 无 | 顺手可加 ED2K / HLS / DASH / SFTP |
| 失败模式 | 编译期就能发现 | 运行时进程崩溃/端口冲突/僵尸进程，需要 supervisor + 端口守卫（Rayburst 为此写了 `engine/supervisor.rs`、`services/port_guard.rs`） |
| 对本项目定位（"体积小 3~8MB"） | **一致** | 需要重新定位 |

**修正后的建议**：**仍以 librqbit（路线①）为首选**，理由是它保住了本项目"无外部二进制、体积小"的定位，
且 Rayburst 的实践反过来说明 sidecar 路线会带来便携版/安装期注册/进程看护三类长期成本。
但如果目标是**最快让 BT 可用**，路线②的 `aria2 sidecar` 是已被验证的成熟选择，
且本方案 §4 的绝大部分设计（任务模型、多文件、文件选择、协议处理器、设置项）**两条路线完全共用**。

> 换句话说：**先把 §4 的架构改造做掉，引擎适配层是一个可以后换的插槽。**
> 建议在 `torrent/` 模块下用一个 trait 把引擎隔离（`add / pause / resume / remove / stats / select_files`），
> 这样先上 librqbit，若不满意再换 sidecar，前端与任务模型零改动。

## 四、目标架构

### 4.1 任务模型协议化（核心改动）

现有 `Task` 保持不变的部分尽量多，只加"协议维度"：

```rust
// src-tauri/src/engine/types.rs
#[derive(Debug, Clone, Copy, PartialEq, Eq, Serialize, Deserialize, Default)]
#[serde(rename_all = "snake_case")]
pub enum TaskKind {
    #[default]
    Http,      // 默认 Http → 旧任务 JSON 反序列化后行为不变
    Torrent,
}

/// 种子的持久化状态（不含运行时句柄）
#[derive(Debug, Clone, Serialize, Deserialize, Default)]
pub struct TorrentMeta {
    /// 原始输入：magnet:... 或本地 .torrent 路径或 .torrent URL
    pub input: String,
    /// v1 info hash（40 位 hex）
    #[serde(default)]
    pub info_hash: Option<String>,
    /// 缓存的最小 metainfo（bencode 原始字节，base64）——重启后无需再进 DHT 解析元数据
    #[serde(default)]
    pub metainfo_b64: Option<String>,
    /// 用户勾选的文件索引；None = 全部
    #[serde(default)]
    pub selected_files: Option<Vec<usize>>,
    /// 已发现的 peer 数 / 上传量（仅用于 UI 与导出）
    #[serde(default)]
    pub uploaded_bytes: u64,
}
```

`TaskInfo`（前端契约）新增字段，全部 `#[serde(default)]` 以免影响旧前端：

```rust
pub struct TaskInfo {
    // ... 现有字段保持不变 ...
    #[serde(default)] pub kind: TaskKind,
    #[serde(default)] pub upload_speed_bps: Option<u64>,
    #[serde(default)] pub uploaded_bytes: Option<u64>,
    #[serde(default)] pub peers: Option<u32>,
    #[serde(default)] pub seeds: Option<u32>,
    /// 种子内文件列表（前端用于展开详情）；HTTP 任务为 None
    #[serde(default)] pub files: Option<Vec<TorrentFileInfo>>,
    /// 元数据是否已就绪（磁力链接刚添加时为 false）
    #[serde(default)] pub metadata_ready: bool,
}

#[derive(Debug, Clone, Serialize)]
pub struct TorrentFileInfo {
    pub index: usize,
    pub name: String,          // 相对种子的路径
    pub length: u64,
    pub progress_bytes: u64,   // 来自 TorrentStats.file_progress
    pub selected: bool,
}
```

`Task` 内部新增（运行时）：

```rust
pub struct Task {
    // ... 现有字段 ...
    pub kind: TaskKind,
    pub torrent: Option<crate::torrent::TorrentRuntime>,   // handle / info_hash / 轮询任务
    /// 动态总大小：BT 在元数据就绪前不知道总大小，HTTP 仍用 total_bytes
    pub total_dynamic: Arc<AtomicU64>,
}
```

**关键点：`total_bytes: Option<u64>` 保持不动**，BT 的总大小走 `total_dynamic`，
`TaskInfo.total_bytes` 在序列化时按 kind 取其一 —— 这样 `writer.rs` / `probe` 路径一行不用改。

```rust
pub struct Scheduler {
    // ...
    torrent: Arc<tokio::sync::OnceCell<Arc<crate::torrent::TorrentEngine>>>,
}
```

用 `OnceCell` 而不是在 `setup` 里初始化，是因为：会话创建需要 tokio 上下文、需要在设置加载之后、
且失败时不应让整个应用启动失败。

### 4.3 一次磁力链接的完整时序（元数据优先）

```
用户粘贴 magnet:?xt=urn:btih:<40hex>&dn=xxx&tr=...
        │
        ├─(1) probe_torrent(input)                       ← 新命令
        │      ├ magnet → Magnet::parse()，立即拿到 info_hash（不联网）
        │      └ 返回 { protocol:"torrent", phase:"resolving", info_hash, name }
        │
        ├─(2) 前端弹「解析中…」；后端 add_torrent(list_only: true)
        │      └ 经 DHT/tracker 解析元数据（可能 5s ~ 数分钟，必须异步）
        │      └ 返回 ListOnlyResponse { info_hash, info, torrent_bytes, output_folder }
        │      └ emit "torrent-metadata" → { name, files:[{index,name,length}], total_bytes }
        │
        ├─(3) 前端「选择要下载的文件」复选框（默认全选）→ create_download(kind:"torrent",
        │      magnet, info_hash, metainfo_b64, selected_files)
        │
        └─(4) start_download → torrent::runner
               └ add_torrent(TorrentFileBytes(metainfo_b64), { only_files, output_folder,
                              overwrite:true, trackers, ratelimits, peer_limit })
               └ spawn stats 轮询器 → 更新 Task.downloaded/total_dynamic → emit download-progress
               └ finished → TaskStatus::Completed + emit download-finished
```

> `list_only` 顺带返回的 `torrent_bytes` 是关键收益：**元数据只需解析一次**。用户重启应用后
> 可以直接用缓存的 metainfo 重新挂载，无需再次进 DHT。

对**已有 metainfo** 的输入（`.torrent` 文件、或用户已在步骤 2 选过文件）可以跳过解析，直接建任务。

### 4.4 状态映射

| 项目 `TaskStatus` | librqbit `TorrentStatsState` / 条件 | 动作 |
|-------------------|-------------------------------------|------|
| `Pending` | 未 add | — |
| `Downloading` | `Live`（`finished == false`） | 轮询更新进度 |
| `Downloading`（元数据阶段） | `Initializing` | 前端显示"解析元数据中…" |
| `Paused` | `Paused` | `session.pause(&handle)` |
| `Completed` | `finished == true` | 按做种策略决定是否 `pause` |
| `Failed` | `Error` | 取 `stats.error` 写入 `error_message` |
| `Cancelled` | `session.delete(id, delete_files=false)` | 保留已下载分片，允许多次续传 |

**暂停/恢复必须双向直达**：`Scheduler::pause_task` / `resume_task` 在 `kind == Torrent` 时
直接调用 `torrent_engine.pause(info_hash)` / `unpause(...)`，而不是"改状态等轮询器发现"——
后者的延迟与竞态会让 UI 手感变差。

### 4.5 进度与限速

```rust
// torrent/runner.rs 轮询体（500ms）
let stats = handle.stats();
task.total_dynamic.store(stats.total_bytes, Relaxed);
task.downloaded.store(stats.progress_bytes, Relaxed);
let (dl, ul) = stats.live.as_ref()
    .map(|l| (l.download_speed.mbps(), l.upload_speed.mbps()))
    .unwrap_or((0.0, 0.0));
// 复用现有事件，前端 App.tsx:73 的 listen("download-progress") 无需改动
app.emit("download-progress", ())?;
```

限速：`session.ratelimits` 是 `pub` 字段，`Limits::set_download_bps()` / `set_upload_bps()`
**是同步方法**，所以可以直接挂在现有的同步入口 `Scheduler::update_from_settings()` 里：

```rust
if let Some(engine) = self.torrent.get() {
    engine.set_download_limit(settings.global_speed_limit_kbps);  // 0 → None
    engine.set_upload_limit(settings.torrent_upload_limit_kbps);
}
```

### 4.6 两级持久化

| 层级 | 位置 | 内容 | 谁负责 |
|------|------|------|--------|
| 任务列表 | `<app_data>/multidown_tasks.json` | `TaskKind`、magnet/info_hash、metainfo_b64、选中文件、已下载字节、状态 | 现有 `engine/persistence.rs`（加字段） |
| BT 会话状态 | `<app_data>/torrent-session/`（`SessionPersistenceConfig::Json`） | 分片位图 fastresume、peer 缓存 | librqbit |
| DHT 节点表 | `DhtPersistenceConfig::default()` | 路由表，加速下次启动 | librqbit |

启动恢复：先 `load_from()` 反序列化任务 → 初始化 `TorrentEngine` → 对每个 `Pending/Paused`
的 BT 任务用缓存的 `metainfo_b64` 重新 `add_torrent(paused: true)`。fastresume 会跳过已完成分片校验。

### 4.7 代理、并发、队列、规则

**代理（必须写清楚，否则有隐私风险）**

| 项 | 结论 |
|----|------|
| 支持的代理类型 | **仅 SOCKS5**（`ConnectionOptions { proxy_url: Some("socks5://user:pass@host:port") }`，scheme 必须是 `socks5://`） |
| 项目现有的 HTTP/HTTPS 代理设置 | BT peer 连接**不支持**，需要给 BT 单独一个 SOCKS5 配置项 |
| 走代理后必须同时做的 | **关闭 DHT 与 LSD**。DHT/本地发现走 UDP，不经 SOCKS，会暴露真实 IP 并宣告 infohash |
| tracker 请求 | 走 librqbit 内部的 reqwest（也吃 SOCKS 配置），但显式 `disable_trackers` 更稳 |
| uTP | 配了代理就自动退化为纯 TCP（源码里 `socks_proxy_config.is_some()` 与 utp 互斥） |

**并发与队列**：一个种子任务占**一个**任务槽位（`can_start_for_queue` 无需改动）；
BT 内部的并行度由 `AddTorrentOptions.peer_limit`（建议默认 50）控制，
**不要**把 `max_connections_per_task` 映射过去（那是 HTTP 连接数，语义不同）。

**分类规则**（`engine/rules.rs`）：命中逻辑基于 URL/文件名扩展名，BT 任务建议按
**种子名 + 内容扩展名**匹配（多文件种子按文件里占比最大的扩展名归类），需要给
`match_rule` 增加一个"候选名字列表"入参。

**去重**（`find_duplicate`）：BT 任务按 `info_hash` 去重，而不是 URL（同一资源的磁力链接
可能带不同的 `dn`/`tr` 参数）。

**导出/导入**：`metainfo_b64` 会让导出文件变大。建议导出时**剔除 metainfo**，
只留 magnet + info_hash（导入后重新解析元数据）。

### 4.8 做种策略

`disable-upload` 是 librqbit 的**编译期 feature**，不适合做运行时开关；而且它**没有 seed-ratio /
seed-time 这类 API**（这点不如 aria2）。所以做种策略必须由我们自己在轮询器里实现：

| 设置项 | 实现 |
|--------|------|
| `stop_on_complete`（默认） | `finished` 后调 `session.pause(&handle)`：停止上传但保留全部数据与位图，随时可恢复做种 |
| `ratio` | 轮询中比对 `uploaded_bytes / total_bytes`，达到阈值后 pause |
| `time` | 记录完成时间，达到 N 分钟后 pause |
| `forever` | 不 pause（需要 `overwrite: true`，且注意磁盘/带宽） |

上传限速用 `set_upload_bps()`；建议默认给一个非零上传限速，避免影响用户正常上网。

### 4.9 OS 集成（磁力链接成为系统默认处理程序）

**现状核对结论（读插件源码，非文档推测）**：

- `tauri-plugin-deep-link` 2.4.10 的 `DeepLink::register(scheme)` **只在 Windows / Linux 有效**
  （Windows 写 `HKCU\Software\Classes\<scheme>`，无需管理员；Linux 写
  `~/.local/share/applications/<bin>-handler.desktop` + `xdg-mime default`）。
  **macOS 返回 `Error::UnsupportedPlatform`**。
  → 注意：这是**插件 API 的限制，不是平台限制**。两个问题决定了我们不使用这个 API：
  ① macOS 上它直接罢工；② 它在 Windows/Linux 上是"直接抢占默认值"，而不是"注册为候选、由用户选择"。
  §3.4 的 Rayburst 三平台实现（`commands/protocol/{windows,macos,linux}.rs`）绕开了该 API，是更好的做法。
- `handle_cli_arguments` 的源码注释明确写着 *"we only match deep links against the schemes defined in
  the Tauri configuration i.e. **dynamic schemes WON'T be processed**"*。
- **Tauri 的 NSIS 模板确实会在安装期注册 scheme**（已从 `@tauri-apps/cli` 2.11.5 二进制内的模板文本
  逐字核对，模板源码：`crates/tauri-bundler/src/bundle/windows/nsis/installer.nsi`）。它遍历
  `plugins.deep-link.desktop.schemes` 并直接写：

  ```nsis
  WriteRegStr SHCTX "Software\Classes\<scheme>" "URL Protocol" ""
  WriteRegStr SHCTX "Software\Classes\<scheme>" "" "URL:${BUNDLEID} protocol"
  WriteRegStr SHCTX "Software\Classes\<scheme>\DefaultIcon" "" '"$INSTDIR\${MAINBINARYNAME}.exe",0'
  WriteRegStr SHCTX "Software\Classes\<scheme>\shell\open\command" "" '"$INSTDIR\${MAINBINARYNAME}.exe" "%1"'
  ```

  卸载时**只在该键仍指向自己时才删除**（安全）。`SHCTX` 由 `bundle.windows.nsis.installMode` 决定：
  默认 `currentUser` → **HKCU，无需管理员**；`perMachine` → HKLM；`both` → 二选一（总要提权）。
  → **这是本方案最重要的一个取舍点**：把 `magnet` 写进 `schemes` 会让**安装器静默把 magnet 抢为默认**
  （因为 `HKCU\Software\Classes\magnet` 就是用户视角的默认关联），而这正是 §3.4 里 Rayburst 想避免的事
  （它在自己的 NSIS 钩子里写的是 ProgID `Software\Classes\<BUNDLEID>.magnet` + `Capabilities`，
  属于"候选"而非"抢占"；但它的 `schemes` 里同样有 `magnet`，所以安装器那一步仍然会直接写默认键）。

- **`RunEvent::Opened` 的接收路径**：`.run(generate_context!())` 拿不到事件，必须改成
  `.build(...)?.run(|app, event| ...)`；该变体仅在 macOS/iOS/Android 编译（Windows/Linux 上根本不存在，
  相关 `match` 必须 `cfg` 隔离）。macOS 上插件 `on_event` 会把 `RunEvent::Opened` 里的 URL
  **不按配置过滤**地送进 `on_open_url`，所以 `file:///…x.torrent` 也会来。

- **capabilities 权限标识**（若前端要调 JS API）：`deep-link:default` **只含 `allow-get-current`**，
  `register/unregister` 需额外加 `deep-link:allow-register` / `deep-link:allow-unregister`。
  Rust 侧 `on_open_url` **不需要任何权限**。另外 `tauri.conf.json` 已开 `withGlobalTauri: true`，
  所以不装 npm 包也能用 `window.__TAURI__.deepLink`。

- **`fileAssociations` 的 schema** 比想象的多：`ext`(必填) / `name` / `description`(Windows 专用) /
  `role`(macOS) / `mimeType`(Linux 的 `MimeType=`) / `rank`(macOS `LSHandlerRank`) /
  `contentTypes` / `exportedType`。**macOS 有个坑**：Tauri 的 `extension_to_uti` 表只覆盖
  图片/视频/音频/pdf/text，`.torrent` 得不到 `LSItemContentTypes`，只会写 `CFBundleTypeExtensions`。
  要拿到现代的 UTI 声明，需要显式加 `contentTypes: ["org.bittorrent.torrent"]`
  或 `exportedType`（具体 UTI 字符串需在真机 `mdls -name kMDItemContentType x.torrent` 确认）。
  两个相关结构体都是 `deny_unknown_fields`：**键名拼错会导致构建失败**（是好事）。

**推荐策略**（已按 §3.4 与插件/打包器源码核对结果修正）

| 平台 | 方案 |
|------|------|
| **Windows** | 两条路必须二选一，因为"能被唤起"和"不抢默认"在 Tauri 默认机制下是冲突的：<br>**A（省事）**：把 `magnet` 写进 `schemes`，接受安装器把它设为默认（Rayburst 实际就是这样）。<br>**B（不打扰用户，推荐）**：**Windows/Linux 的配置里不放 `magnet`**，自己在 single-instance 回调与 `std::env::args()` 里解析 argv（磁力就是 `argv[1]`）；关联则用 NSIS 钩子注册**候选**：`Software\RegisteredApplications` + `Software\<BUNDLEID>\Capabilities\URLAssociations` + ProgID `Software\Classes\<BUNDLEID>.magnet`，再用 `AssocQueryStringW` 查询当前默认、把用户引导到 `ms-settings:defaultapps?registeredAppUser=<identifier>` 让其自行选择；`SHChangeNotify` 刷新壳。卸载只删仍指向自己的键。参考 `rayburst/src-tauri/nsis/hooks.nsh`、`commands/protocol/windows.rs` |
| **macOS** | **必须在 `schemes` 里声明 `magnet`**（否则 Info.plist 里没有 `CFBundleURLTypes`，LaunchServices 不会把 `magnet:` 交给我们），声明只是"成为候选"。运行时切换默认：`LSSetDefaultHandlerForURLScheme("magnet", bundle_id)`；`.torrent` 用 `UTTypeCreatePreferredIdentifierForTag` 得到 `public.filename-extension:torrent` 后走 `LSSetDefaultRoleHandlerForContentType`；`status == -128` = 用户取消。查询用 `NSWorkspace.URLForApplicationToOpenURL` / `LSCopyDefaultRoleHandlerForContentType`。参考 `commands/protocol/macos.rs`（106 行，含 FFI 声明，可直接移植） |
| **Linux** | 用 **GIO**（`gio::AppInfo`/`DesktopAppInfo`）而非 shell 调 `xdg-mime`：写 `.desktop`（`MimeType=application/x-bittorrent;x-scheme-handler/magnet;`，打包器会自动把 `schemes` 展开成 `x-scheme-handler/*`）→ 用 GLib 解析 `Exec` **校验该 desktop 条目确实属于自己** → `set_default`。注意：**AppImage 里的 `.desktop` 不会自动安装**，除非用户做了 AppImage 集成——这正是 `register_all()` 的适用场景。插件自带的 `register()` 还需要系统装有 `xdg-mime` 与 `update-desktop-database`，且 `unregister()` 在 `~/.config/mimeapps.list` 不存在时会报错。参考 `commands/protocol/linux.rs`（436 行） |

> 三平台都需要在 `tauri.conf.json` 里声明 `magnet` scheme（否则 §4.9 前面说的
> `handle_cli_arguments` 根本不会把 URL 交给我们），但**"声明"与"抢默认"是两件事**：
> 声明只是让应用成为候选，是否成为默认由上面各平台的注册逻辑与用户选择决定。

**关键实现技巧：`schemes` 是"一份列表作用于三个平台"，而上面的选择是分平台的。**
解决办法是**用平台专属配置文件分层**——本项目已经在用这套机制（`tauri.macos.conf.json`、
`tauri.windows.conf.json`、`tauri.nsis.conf.json`），Tauri 会把它们合并到基础配置之上：

| 文件 | `plugins.deep-link.desktop.schemes` | 效果 |
|------|--------------------------------------|------|
| `tauri.conf.json`（基础） | `["multidown"]` | 不注册 magnet |
| `tauri.macos.conf.json` | `["multidown", "magnet"]` | Info.plist 里有 `CFBundleURLTypes` → LaunchServices 会把 `magnet:` 路由给我们（仍需运行时 `LSSetDefaultHandlerForURLScheme` 才会成为**默认**） |
| Windows / Linux | 继承基础配置（无 `magnet`） | NSIS 与 `.desktop` 都不会自动抢默认；magnet 由我们自己解析 argv + 自行注册候选处理程序 |

这样既满足 macOS 的"必须声明"，又满足 Windows/Linux 的"不静默抢占"。

> 待实测确认：平台配置文件的合并语义中，数组是**替换**还是**拼接**。本方案依赖"替换"
> （macOS 覆盖基础列表）。落地时用 `tauri build --debug` 后检查 `.app/Contents/Info.plist` 的
> `CFBundleURLSchemes` 是否恰好是 `["multidown","magnet"]` 即可确认。

**`.torrent` 文件关联**（打开文件，不是 URL）：

```json
"bundle": {
  "fileAssociations": [{
    "ext": ["torrent"],
    "name": "BitTorrent Metainfo",
    "description": "BitTorrent 种子文件",
    "mimeType": "application/x-bittorrent",
    "role": "Viewer"
  }]
}
```

接收路径因平台而异：

- **macOS**：`RunEvent::Opened { urls }`（该变体仅在 `macos/ios/android` 编译，已在 Tauri 2.11.5 源码确认）。
  需要把 `lib.rs` 结尾的 `.run(tauri::generate_context!())` 改成
  `.build(...)?.run(|app, event| { if let RunEvent::Opened { urls } = event { ... } })`。
- **Windows / Linux**：文件路径通过 argv 传入；首次启动读 `std::env::args()`，
  已运行时靠 single-instance 回调的 `args`。
- **全平台兜底**：窗口拖拽（`tauri://drag-drop` 事件），这是体验最好、也最不依赖系统关联的入口，
  建议**优先实现**。

三个来源（macOS 的 `Opened`、argv、single-instance 的 `args`）应当汇入**同一个解析函数**，
判定规则抄 Rayburst 的 `filter_external_input_args`（`services/deep_link.rs`，其单测可直接移植）：

```rust
fn is_external_input(arg: &str) -> bool {
    if arg.starts_with('-') { return false; }          // 忽略 CLI 开关与 autostart 参数
    let lower = arg.to_lowercase();
    lower.contains("://")                               // magnet: / ed2k: / file:///x.torrent
        || lower.starts_with("magnet:")
        || lower.ends_with(".torrent")                  // Windows/Linux 的裸文件路径
}
```

注意 macOS 给的是 **`file:///...torrent`** 而不是裸路径，所以本地文件必须先做 `file:` URL → 路径的转换。
建议同时保留一个"前端未就绪时入队、就绪后 drain"的待处理队列（Rayburst 的
`PendingDeepLinkState` 是完整实现），规模不大但能消除一类偶发丢事件。

**顺带修复的现存缺陷**：`src-tauri/src/lib.rs:1840` 注册 single-instance 时没开 `deep-link` feature，
而插件源码显示只有开了该 feature 才会在二次启动时调用 `deep_link.handle_cli_arguments(args)`。
也就是说 **Windows/Linux 上"应用已在运行时点击 `multidown://` 链接"目前不会触发任何行为**。
改动：`tauri-plugin-single-instance = { version = "2", features = ["deep-link"] }`。

> 但请注意该 feature 的一个**竞态**：single-instance 的 setup 早于 deep-link 的 setup（后者才
> `app.manage(DeepLink)`），若第二个实例恰好落在这个空窗期，`try_state::<DeepLink>()` 为 `None`，
> **URL 会被静默丢弃**。由于我们本来就要为 `.torrent` 文件路径自己解析 argv（插件不处理非 URL 参数），
> 建议**统一自己解析 argv**，不要依赖插件的转发——这样既避开竞态，也避开了"必须把 `magnet` 写进
> `schemes` 才会被转发"的约束（见下面的 A/B 选择）。

## 九、待你决策的问题

1. **先确认功能缺口能不能接受——这条会直接决定路线。** librqbit **没有 BEP 19 web seed、
   没有 MSE/PE 连接加密**。如果你的目标用户里有**私有 tracker（PT）**用户，加密是硬需求，
   那路线①直接出局，必须走 aria2。这个问题的优先级高于体积和 MSRV。
2. **引擎路线选哪条？**
   - **路线① 内嵌 `librqbit`**：保住"无外部二进制、体积小"的定位，Apache-2.0 无许可负担；
     代价是 MSRV ≥ **1.88**、二进制 **实测 +6.33 MiB**、`Cargo.lock` 净 +108 个包、reqwest 双版本，
     以及上面第 1 条的三个能力缺口。
   - **路线② aria2 sidecar**（Motrix Next/Rayburst 路线）：BT 最成熟（含 web seed 与加密），
     还能顺带拿到 ED2K/HLS；代价是每平台多发一个二进制、**无法做便携版**、需要进程看护、
     **GPL-2.0 合规义务**，项目定位要重新说明。
   - 无论选哪条，§4 的架构改造（任务模型/多文件/文件选择/协议处理器/设置项）**完全共用**，
     所以也可以"先把 §4 做掉，引擎用 trait 隔离，之后再换"。
3. **是否接受 MSRV 提升到 1.88 与二进制体积 +6.33 MiB？**（仅路线①相关；建议顺手把
   `rust-version` 从错误的 `"1.70"` 改成真实值）
4. **多文件种子在任务列表里怎么呈现？** 方案 A：一个种子 = 一个任务，详情里展开文件（推荐，改动小，
   与 Rayburst 一致）；方案 B：每个文件生成一个子任务（更接近 IDM 的列表语义，但要引入父子任务模型）。
5. **要不要主动抢占磁力链接默认程序？** 建议按 §4.9 做成"注册为候选 + 引导用户去系统设置选择"，
   而不是静默抢占。
6. **是否首期支持私有 tracker（PT）？** 需要 cookie/passkey 注入与更细的 tracker 控制；
   **注意这同时决定了引擎选型**（见第 1 条）。
7. **要不要做 tracker 列表自动同步？**（Rayburst 有：从用户配置的 URL 拉取 tracker 列表并写入引擎配置，
   带代理支持与分源失败上报，`commands/tracker.rs` 约 200 行，可移植性很好。）
8. **要不要做边下边播**（`handle.stream(file_id)`）？可以作为 T6 之后的独立增强。
9. **BT 监听的默认端口怎么定？** 固定端口（如 6881）便于用户做端口映射，但会和其它 BT 客户端冲突；
   随机端口不冲突但不利于连通性。建议默认随机 + 提供"固定端口"选项。
