# 数据持久化与恢复

Multidown 将应用状态放在 Tauri 返回的应用数据目录，而下载内容写入用户选择的目录。具体平台位置见后续的[参考文档](../README.md#我负责发布维护)，业务代码不应硬编码用户目录。

## 持久化内容

- `multidown_settings.json`：用户设置，包括下载、代理、捕获和 BitTorrent 配置。
- `multidown_tasks.json`：HTTP/BT 任务、剩余区间、校验元数据和协议特有状态。
- `category_rules.json`：分类匹配规则。
- `schedule_rules.json`：定时调度规则。
- `proxies.json`：命名代理和域名分流规则。
- 队列数据：调度器初始化时加载并在变更后保存。
- `torrent-session/`：librqbit fastresume 和会话状态。
- `native_host_port.txt`：当前进程的临时回环端口，退出时尽力删除。
- `multidown.log`：应用诊断日志。

批次主要是运行时编排信息，不应假定所有瞬时 UI 状态都会跨重启恢复。

## 兼容策略

持久化结构使用 Serde。新增可选字段通过 `#[serde(default)]` 给旧文件提供语义明确的默认值：例如旧任务没有 `kind` 时恢复为 HTTP，没有种子元数据时保持为空。兼容回归测试使用真实旧格式样本，防止升级后丢失既有任务字段。

删除或改名字段需要迁移策略和回归 fixture，不能只让当前版本写出的 JSON 自洽。枚举值变化同样属于数据迁移。

## 写入与崩溃恢复

任务在关键状态变化以及配置的周期间隔保存。异常退出时，内存中最后一次保存之后的进度可能丢失，但目标文件已有字节不会凭空消失；HTTP 恢复会依据剩余区间与远端校验信息决定续传或重下。

当前部分 JSON 保存使用直接写入目标文件，并非所有文件都具备事务性临时文件替换。磁盘写满或进程在写入中终止可能造成 JSON 损坏；这是需要后续加强的可靠性边界。重要下载内容应自行备份，诊断损坏时先复制应用数据目录再操作。

## 敏感数据

任务可持久化认证配置与自定义请求头，设置和代理文件可能包含凭据。它们依赖操作系统用户目录权限，并未声明由应用额外加密。日志和问题报告不得包含 Cookie、Authorization 或代理密码。
