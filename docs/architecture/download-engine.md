# HTTP 下载引擎

## 创建与探测

任务创建先解析 URL、认证和请求头，再通过 HEAD 或必要的 GET 请求探测文件大小、文件名、`Accept-Ranges`、`ETag` 与 `Last-Modified`。`Content-Disposition` 优先于 URL basename。不能确认 Range 支持时使用单连接路径。

分类规则可根据域名或扩展名选择保存位置；重复链接策略在任务落库前决定询问、跳过、覆盖或重命名。浏览器入口还会应用捕获总开关与域名黑名单。

## 调度与队列

`engine/scheduler.rs` 是统一协调点。全局并发上限与队列并发上限取更严格的约束，暂停的队列不会启动新任务。批次分批探测并创建任务；定时调度以周期 tick 执行开始、暂停、恢复或临时限速。设置更新会同步到调度器和令牌桶。

队列与批次的生命周期是完整的：创建、更新、删除、排序、任务分配与移出都有对应命令。删除队列是软删除且默认队列不可删除；删除批次不连带删除批次已创建的下载任务。队列策略变更与任务准入共用同一把生命周期锁，因此暂停或删除队列不会插进“校验 → 预留并发槽”之间。

## 动态分段

支持 Range 的任务以未完成字节区间表示进度。工作连接从最大的未完成区间取任务，并在满足最小粒度时动态二分，让快连接继续领取工作，避免固定分段中慢连接拖尾。过小区间不再拆分，防止碎片和调度开销无限增长。

服务器不支持 Range 时只保留一个顺序区间。每个分段独立重试并使用退避；任务级重试次数由设置控制。

## 写入与完成

网络响应按块读取，`writer.rs` 根据 offset 写入目标文件，不把整个分段保存在内存中。任务进度和剩余区间按设置间隔持久化。

存在已保存 `ETag` 时，续传请求携带 `If-Range`；服务器返回全量响应表示条件不再满足，任务会整体重新下载。`Last-Modified` 当前虽会被探测和持久化，但尚未作为无 ETag 场景的 `If-Range` 条件，因此这类服务器不能获得同等的远端变更保护。只有所有区间完成并成功写盘后才进入完成状态；通知和完成对话框属于其后的 UI 行为。

## 限速与代理

全局下载限速由共享令牌桶执行，计划任务可以在时间窗内临时覆盖。HTTP 客户端支持无代理、系统代理、手动代理和规则分流；当前 `domain_contains` 规则实际匹配完整 URL 子串，而不是解析后的 host。任务级认证和请求头覆盖全局默认值，但 TLS 证书验证始终开启。

## 失败恢复

网络错误、HTTP 状态、文件写入、磁盘空间和权限错误分别保留可操作的失败信息。重启后恢复的是已持久化的安全点，最近一次周期保存后的少量进度可能需要重下。恢复的具体判定与启动顺序见[持久化架构](./persistence.md#启动顺序)。

## 删除事务

删除任务是一次三步事务，**数据文件删除是默认关闭的选项**，不是副作用：

1. **先停**。HTTP 任务持久化取消状态并等待 worker 退出（worker 退出前会等写入器落盘并关闭文件句柄）；种子任务摘除会话句柄但保留数据。停止失败立即中止，任务原样保留。
2. **再删（可选）**。`delete_files = true` 时才删除数据文件，且必须通过保存目录边界校验：现存目标 `canonicalize` 之后仍须位于配置的默认保存目录之内，且不得就是保存目录本身；符号链接与 `..` 逃逸因此被拒绝。目标不存在视为幂等空操作。删除失败时任务**不会消失**：它被写成 `Failed` 并带上 `error_message` 后重新落盘。
3. **最后移除记录**。走跨存储的回滚事务移除任务记录，前面的步骤全部成功才会执行。

删除预览（`preview_task_deletion`）与实际删除共用同一份候选路径来源：HTTP 任务的目标文件本身；种子任务还包括按解析后的种子名离线算出的数据位置。预览返回路径清单与 `can_delete_files`，界面据此禁用越界时的“同时删除文件”。

## 落盘串行化

所有任务落盘入口共用一把生命周期锁（`lifecycle_persist_lock`），因此状态转换、批量提交、批量删除和整表保存不会互相交错。它关闭的是一个真实存在的串行化缺口，**不代表** Windows 上偶发的 `os error 5` / `os error 32` 已被解释或修复——那个缺陷仍未定位，见[持久化架构](./persistence.md#已知可靠性缺口)。
