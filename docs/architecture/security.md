# 安全模型

本页描述实现边界，不代替漏洞报告流程；报告安全问题请遵循根目录[安全策略](../../SECURITY.md)。

## 目标与不可信输入

目标是把网络和浏览器输入限制在用户明确选择的下载行为内，避免越权文件访问、证书绕过、代理泄漏和隐式系统关联。以下内容一律视为不可信：URL、重定向、响应头、文件名、种子元数据、peer 消息、浏览器 JSON、深链、argv、拖入路径和导入文件。

Rust 后端必须完成最终协议、范围和路径检查；前端校验只改善体验，不能作为安全边界。

## 网络安全

- HTTP 客户端严格验证 TLS 证书，不提供“忽略证书错误”选项。
- 自签环境通过操作系统可信 CA 管理，不把关闭校验作为排障方案。
- 代理规则按解析后的 URL host 匹配，避免把未经解析的字符串当域名。
- BT SOCKS5 启用时关闭 DHT 与本地发现，减少 UDP 绕过代理；该行为不保证匿名。
- 外部 HTTP 响应和种子数据仍可能消耗大量带宽、磁盘或连接，应通过限速、并发和空间监控约束。

## 浏览器与本机 IPC

Native Host 清单限制固定扩展身份；应用回环服务只绑定 `127.0.0.1` 并使用随机端口。扩展发送的 URL 在应用侧再次验证，捕获总开关和黑名单不能只依赖扩展执行。

安装引导只启动浏览器管理页和展示手工加载步骤，不终止浏览器、绕过策略或静默安装未经审阅的扩展。深链与 Native Host 使用相同的不可信输入原则。

## 文件与平台能力

下载写入必须使用用户确认或规则选择的路径，远端文件名不能获得任意路径控制。覆盖、删除、移动和重命名属于高风险操作，需要明确策略和错误反馈。

Tauri capability 明确列出主窗口可用的核心、通知、对话框和文件权限。当前配置允许主窗口读取 `$HOME/**` 下的文本文件，这比理想的最小范围更宽；敏感操作仍应通过受控 Rust 命令完成，未来应在功能拆分后收紧 capability。

磁力与 `.torrent` 关联只注册候选应用，不能静默抢占用户现有默认程序。平台适配器应使用用户级配置并可恢复。

## 数据保护

任务、请求头、代理配置和日志存放在用户应用数据目录，当前不提供应用层静态加密。文档、日志和 Issue 必须脱敏。发布产物和扩展签名私钥不得进入仓库。

## 已知安全限制

- 回环 TCP 服务当前没有会话令牌；同一用户权限下能读取端口或扫描本机端口的恶意进程可能尝试提交受支持的 URL。
- 主窗口文本读取 capability 覆盖用户主目录，权限范围仍可进一步缩小。
- 部分 JSON 状态写入不是完全事务化，损坏更偏向可用性/完整性风险。
- 不支持 BitTorrent MSE/PE；不要把传输当作隐藏流量或身份的机制。
- 浏览器开发者模式扩展不是应用商店信任替代品，用户必须核对来源和固定身份。

这些限制应在威胁评审和后续版本中持续跟踪，不应被用户文档中的简化措辞掩盖。
