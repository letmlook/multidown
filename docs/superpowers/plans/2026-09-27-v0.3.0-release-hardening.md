# Multidown v0.3.0 Release Hardening Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Turn the current BitTorrent-capable `main` into a safely installable, automatically tested, documented, and publicly released Multidown `v0.3.0`.

**Architecture:** Extract browser integration and BitTorrent settings behind focused interfaces while preserving all existing Tauri command names and settings fields. Add behavior-first tests around the extracted seams and existing Rust state machines, then make three-platform CI the release gate before tagging and publishing.

**Tech Stack:** Tauri 2, Rust 1.88, React 18, TypeScript 5.6, Vite 5, Vitest, ESLint 9, GitHub Actions, GitHub CLI.

**Spec:** `docs/superpowers/specs/2026-09-27-v0.3.0-release-hardening-design.md`

## Global Constraints

- Publish a new `v0.3.0`; never overwrite, delete, or reuse `v0.2.0` history.
- No code path may invoke `pkill`, `killall`, `taskkill`, or an equivalent process-termination command.
- Preserve existing Tauri command names, persisted settings fields, and download behavior.
- Require Windows, macOS, and Linux Test Build success before tagging.
- Keep the Release as a draft until expected assets are present and inspected.
- Limit refactoring to browser integration and the BitTorrent section of `OptionsModal`.

## Review Focus

- A missing extension directory or `manifest.json` must return an actionable error without starting or terminating a browser; covered in Task 1.
- A machine with no supported browser must return the manual-install fallback without panicking; covered in Task 1.
- Existing users with partial/legacy torrent settings must still see documented defaults; covered in Task 2.
- Queue/schedule windows spanning midnight and persisted pre-torrent task JSON must remain valid; covered in Task 3.
- A release workflow with an incomplete platform asset set must remain a draft and abort publication; covered in Task 7.
