# 已知限制

本页汇总当前稳定版本 `v0.3.0` 的已知边界与**当前验证状态**。它们不是未来版本承诺；实际计划以仓库后续 Issue、Pull Request 和 Release 为准。

本页的写法要求：只记录**真实存在的边界**。一个能力还没做到，就写“尚未支持/尚未验证”，不要因为实现了困难就悄悄删掉它的承诺。

## 验证状态

本节是判断“某条结论能不能信”的依据。文档中任何平台行为的描述都必须能归到下面四类之一。

| 类别 | 含义 |
| --- | --- |
| 本机已验证 | 在 Windows 开发机上真实执行过命令或流程，命令与结果见[测试指南](../development/testing.md) |
| CI 已验证 | 只有三个平台的 CI 任务真正跑过才算。**本分支的三平台 CI 一次都还没有跑过**，因此当前没有任何结论属于这一类 |
| 仅测试覆盖 | 有单元/集成/契约测试保证代码路径，但没有在真实系统或真实软件中执行 |
| 未验证 | 既没有测试覆盖，也没有在真实环境跑过 |

本轮改动在本机（Windows）已实际验证的范围：

- `cargo test --lib`：**212 passed / 0 failed / 1 ignored**。唯一 ignored 的是依赖公网 DHT 的磁力烟雾测试，按设计不进 CI。
- 应用的集成目标需要显式 `--features integration-tests` 才会执行，裸 `cargo test` 会**静默跳过**并报告成功；CI 已加守卫步骤在跑测试之前断言两个目标确实出现在清单里。
- 两个集成目标本机全过：`http_resume` 真实打断一次 Range 传输并验证恢复后字节完全一致且无重复请求；`torrent_restart` 验证文件选择、做种策略、保留/删除数据与会话摘除。
- `integration/native-protocol` 26 个测试；`integration/native-host` 10 个单元 + 10 个 `round_trip` 往返测试（真实 Host 二进制、真实分帧 stdin、真实回环桌面端桩）。
- 前端 `npm run test:run` / `npm run lint` / `npm run docs:check` 在本机通过。

以下**尚未验证**，任何文档都不得声称它们已通过：

- **三平台 CI 一次都没有跑过**。`rust-format` 与固定 Rust 1.88 的 MSRV 任务同样是新加的，同样还没有运行结果。macOS 与 Linux 上的编译、测试与打包因此都是未知数。
- 本轮改动的 unix 分支只做过 `x86_64-unknown-linux-gnu` 的**类型检查**（type-check）与 clippy，**从未执行**。所有 `#[cfg(unix)]` 断言在 macOS/Linux 上仍然只有静态检查，没有运行结果。
- **真实浏览器与真实 GUI 行为完全未验证**：扩展在真实浏览器中的安装与加载、Native Host 与真实浏览器的握手、托盘图标与菜单、系统通知、`.torrent` 文件关联、打开文件/目录、深链注册与冷启动。这些项属于人工验收，逐项记录在[功能验收清单](../development/functionality-release-checklist.md)，当前全部是 `not-run`。
- `rust-version = "1.88"` 的下限未经真实 1.88 工具链验证（需要 CI 的 MSRV 任务）。

## 真实缺陷（尚未修复）

### Windows 上状态写入偶发失败

`storage::save_store` 在 Windows 上间歇性失败，报 `os error 5`（拒绝访问）或 `os error 32`（文件被占用），约每 6 次“种子在恢复瞬间完成”出现 1 次。

- **影响**：那一次任务状态**没有保存成功**。上一次成功保存的内容仍然完整，目标文件不会损坏，但重启后可能回到更早的状态。
- **已经做了什么**：应用内部给所有任务落盘入口加了一把串行化锁。此前并非所有落盘入口都持锁，这是一个真实存在的缺口，已关闭。
- **没有做什么**：这**没有**修掉上面的报错。最强的证据表明进程内并发解释不通——并发最强的测试场景（`join!` 同时发起两次整表落盘，8 轮 × 16 次写）一次都没有复现。疑似外部文件句柄（例如杀毒软件、索引或同步工具以不允许 `FILE_SHARE_DELETE` 的方式持有刚写好的 store 文件）导致原子替换失败。
- **状态**：**未定位**。日志里表现为 `[persistence-error] …` 开头的行。
- **你能做的**：在问题定位前不要依赖跨重启的进度保存；重要文件完成后自行校验；观察到该日志请记录系统上运行的实时安全/同步软件。

### 扩展在本地保存敏感数据

扩展把**完整下载地址和 cookie** 存进浏览器的 `chrome.storage.local`，并提供一个 `export_logs` 动作把这些内容**写入一个文本文件**。这是真实存在、尚未修复的问题（属产品层面的修复，不在 CI 与文档范围内）。导出日志前请自行确认文件不会外流；不要把导出的日志直接发到公开 Issue。

## 暂不支持的功能

- BitTorrent web seed（BEP 19）。
- BitTorrent MSE/PE 连接加密。
- BitTorrent 顺序下载或边下边播保证。
- 完整端到端 UI 自动化测试；当前以关键组件、纯函数、Rust 单元/集成测试和人工平台验收为主。
- Firefox 扩展的仓库内长期签名分发；开发构建通过临时加载验证。
- 仓库不产出 CRX，也不再把 CRX 作为任何构建或安装步骤的前提。需要 CRX 的场景由用户按 `npm run sign:crx` 打印的 Chrome 手工步骤自行处理（该脚本不生成任何文件）。

## 平台与浏览器差异

- 发布资产目前覆盖 Windows x64、macOS Intel/Apple Silicon 和 Linux x64，不提供 Windows ARM64 或 Linux ARM64 安装包。
- 浏览器扩展必须同时具备正确扩展身份、Native Host 清单和桌面应用；Chromium 衍生浏览器可能使用不同注册位置。
- **Native Host 二进制是单独安装的**：只有应用的“安装浏览器扩展”动作会把它复制到浏览器的 host 目录。只升级应用不会升级浏览器里的 Host，升级后连接异常应先重新执行一次该动作。这是设计使然（保证新应用与已安装的旧 Host 双向兼容），不是缺陷。
- 桌面端与 Native Host 解析同一个应用数据目录端口文件（含 Linux 遵循 XDG **数据**目录而非配置目录），这一点由共享协议 crate 逐平台测试固定；但**真实发行版安装下的实际路径仍未验证**。
- 系统通知、托盘、自启、深链、磁力关联、安装与卸载只能在真实平台环境完整验收；三平台 CI 主要证明构建与自动测试通过（而本分支的 CI 尚未首次跑通）。

## 网络相关限制

- 服务器不支持 Range 时只能单连接下载。
- 带时效签名、登录态或防盗链的 URL 可能需要 Cookie、Referer、User-Agent 或认证信息，且过期后无法恢复。
- HTTP 续传只在已有 ETag 时发送 `If-Range`；仅提供 `Last-Modified` 的服务器发生内容变化时，当前版本可能无法阻止新旧分段混合。
- 公网磁力元数据依赖可用 peer、tracker、UDP/DHT；没有活跃来源时可能无限等待。
- BT SOCKS5 代理会关闭 DHT 和本地发现以减少泄漏，因此可发现 peer 数量可能下降。
- TLS 始终严格验证，不提供忽略证书错误的选项。

## 安全与可靠性边界

- 回环 TCP 桥接没有独立会话令牌，同一用户权限下的恶意本地进程属于剩余风险。连接的“应用在运行”判据是带 `multidown` 标记的完整 TCP 握手，因此残留端口文件不会被误判为已连接。
- 扩展在浏览器本地保存完整 URL 与 cookie，并可经 `export_logs` 导出，见上文“真实缺陷”。
- HTTP 建议文件名和部分外部自定义文件名尚未统一限制为 basename；不可信文件名可能包含绝对路径或父目录段并越出预期下载目录。**删除任务的数据文件删除则受保存目录边界保护**（越界目标会被拒绝）。
- `domain_contains` 代理规则当前匹配完整 URL 子串，不是规范化 host，可能因 userinfo、相似域名或路径文本误分流。
- Tauri 主窗口当前可读取 `$HOME/**` 下文本文件，capability 仍有收紧空间。
- 任务请求头、代理配置和日志没有应用层静态加密，依赖操作系统用户目录权限。
- 扩展开发者模式加载便于验证，但不等于应用商店审核或签名信任。

细节及缓解方式见[安全模型](../architecture/security.md)、[持久化架构](../architecture/persistence.md)与[浏览器集成架构](../architecture/browser-integration.md)。

## 开发工具风险

- 当前前端工具链支持 Node.js 20/22；Node.js 24 可能因 Rollup 原生模块签名出现 `ERR_DLOPEN_FAILED`。
- 仓库没有 `.gitattributes`，Windows 上 `core.autocrlf=true` 的工作区是 CRLF 检出。文档检查器已自行归一换行符（`scripts/check-docs.mjs`），但**手工 diff 或脚本按字面量匹配换行时仍需注意**。
- `OptionsModal.tsx`、`src/index.css` 和 `src-tauri/src/lib.rs` 体积较大，修改时更容易产生跨功能回归。
- 公网 DHT 冒烟测试默认忽略，CI 不验证真实公网可达性。
- 完整 npm 依赖树可能含开发工具链审计告警；升级需要单独评估构建兼容性，不能在无验证时自动强制修复。

遇到具体症状先查看[故障排查](../user-guide/troubleshooting.md)，开发者再运行[测试指南](../development/testing.md)中的对应门禁。
