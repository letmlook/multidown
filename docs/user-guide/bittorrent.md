# BitTorrent 使用指南

Multidown 内嵌 BitTorrent 引擎，可处理磁力链接和本地 `.torrent` 文件，无需安装外部下载器。

## 添加任务

- 在新建任务中粘贴 `magnet:` 链接。
- 点击种子文件选择按钮打开 `.torrent`。
- 将 `.torrent` 文件拖入应用窗口。
- 从浏览器扩展的磁力链接右键菜单发送任务。

解析完成后可勾选需要下载的文件。对于裸磁力链接，应用可以先创建占位任务并显示“解析元数据中…”；文件列表需要从 DHT、tracker 或 peer 获取，速度取决于网络和种子活跃度。元数据就绪后可在任务菜单中再次调整文件选择。

## 做种策略

“选项 → BitTorrent”提供四种下载完成后的行为：

- 完成即停止做种（默认）。
- 达到目标分享率后停止。
- 达到指定做种时长后停止。
- 一直做种，直到用户暂停或退出。

可单独设置上传限速和每个种子的 peer 连接上限。若选择持续做种，建议设置非零上传限速，避免占满上行带宽。

## 重启后的行为

- 种子会话状态保存在应用数据目录的 `torrent-session/`（含 fastresume），重启后**不需要重新添加种子**。
- 上次活动中的种子会按文件选择、做种策略和上传量重新接管；上次已经完成下载的种子按当时的做种策略决定是继续做种还是不再启动。
- 恢复出来的种子**先被置为暂停**，再由队列与并发准入决定何时真正开始传输。因此启动时不会有一批种子同时抢带宽；你主动暂停的任务保持暂停。
- peer 连接上限对恢复出来的种子同样生效。注意它的生效路径与新建任务不同：恢复出来的种子已经在会话里，重新添加会命中“已存在”并忽略新参数，所以上限取自**会话级配置**。改完 peer 上限后请重启应用。
- 如果某条种子记录在恢复时无法重建，界面会出现启动恢复警告并给出隔离文件位置，详见[快速上手](./getting-started.md#启动恢复警告)。

以上恢复行为有自动化集成测试覆盖（在 Windows 开发机上真实跑过），但**尚未在真实 macOS/Linux 环境以及真实 BT 网络中验证过**。当前验证状态见[已知限制](../reference/known-limitations.md#验证状态)。

## 网络与隐私

- DHT 用于无 tracker 或 tracker 不可用时寻找 peer。
- 本地发现（LSD）默认关闭，可减少局域网暴露。
- 配置 BT 专用 SOCKS5 代理后，应用会强制关闭 DHT 与本地发现，避免这些 UDP 路径绕过代理暴露真实 IP。
- 监听端口、DHT 和代理设置在重启应用后生效。

代理只能降低部分网络暴露风险，不能提供匿名保证。请遵守所在地法律和内容授权要求。

## 系统关联

Multidown 只注册为磁力链接和 `.torrent` 文件的候选应用，不会静默覆盖现有默认客户端。可在“选项 → BitTorrent”中请求设置磁力链接处理程序，或通过操作系统的默认应用设置完成选择。

## 当前限制

- 不支持 web seed（BEP 19）。
- 不支持 MSE/PE 连接加密，因此某些要求加密的私有 tracker 场景不适用。
- 不支持顺序下载或边下边播保证。
- 没有活跃 peer、DHT 被网络阻断或 tracker 不可达时，磁力元数据可能长期无法完成。

若任务一直停在元数据解析或没有 peer，参见[故障排查](./troubleshooting.md#磁力任务一直显示解析元数据中)。
