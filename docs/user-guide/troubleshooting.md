# 故障排查

先按症状定位，再收集版本、系统、任务地址类型和完整错误文本。日志或截图对排查很有帮助，但分享前应移除 Cookie、认证头、代理密码和个人路径。

## 应用无法启动或窗口空白

1. 确认安装包架构与系统一致。
2. Windows 检查 WebView2 Runtime；Linux 检查 WebKitGTK 等 Tauri 运行依赖。
3. macOS 检查“隐私与安全性”中的拦截提示。
4. 从终端启动应用以获取标准错误输出，但不要用管理员或 root 身份长期运行下载器。

## 启动后出现“启动恢复警告”

这表示**部分下载记录无法恢复，但原始数据已被保留**，不是数据丢失。

- 展开警告看具体范围（任务、队列、分类规则、定时调度等）和原因。
- 警告里的“隔离或备份位置”是真实文件路径，通常与应用状态文件同目录（文件名形如 `<存储名>.recovery-<时间戳>.json`），可以直接打开查看被拒绝的原始记录。
- 点“忽略”只关闭本次会话的提示，**不会删除隔离文件与备份**；重启应用会再次提示。
- 常见原因：单条记录字段缺失或类型不对、整份状态文件被外部程序写坏、迁移期间写入失败。整份文件损坏时，原文件字节级保留在隔离文件中，应用不会用空状态覆盖它。
- 确认隔离文件里的内容无误后，可以把对应状态文件从 `.bak` 备份链里恢复，再重启应用。

## 任务列表没有保存成功

日志或终端输出里出现 `[persistence-error] … os error 5`（拒绝访问）或 `os error 32`（文件被占用）时，说明状态文件这一次没有写成功；上一次成功保存的内容仍然完整，任务本身不会因此损坏。

- **这是尚未定位的缺陷**，不是配置错误。Windows 上约每 6 次“种子在恢复瞬间完成”出现 1 次。应用内部已加写入串行化锁，但它没有解决这个现象。
- 最可能的方向是外部程序正持有刚写好的文件（例如杀毒软件、索引工具、同步客户端、备份程序以不允许删除的方式打开它）。可以临时关闭可疑的实时扫描或同步客户端后重启应用，观察是否还出现。
- 在问题定位之前，重要任务请不要依赖跨重启的进度保存；完成后自行校验文件。
- 详见[已知限制](../reference/known-limitations.md#安全与可靠性边界)。

## HTTP 任务探测失败

- 在浏览器中确认 URL 尚未过期，且不是需要网页脚本生成的一次性地址。
- 对登录资源补充正确的 Cookie、认证方式、Referer 或 User-Agent。
- 某些服务器拒绝 HEAD 请求或 Range 请求；重试后仍失败时，记录状态码和响应头。
- 检查系统时间、DNS、代理和防火墙。公司网络可能拦截未知客户端。

## 下载无法续传或重新从零开始

服务器可能不支持 Range，或远端 `ETag` 已变化。带 ETag 的续传条件不再满足时，Multidown 会整体重下；仅有 `Last-Modified` 的服务器当前不能获得同等保护。也应确认临时文件和目标目录仍可写、磁盘空间充足，并对重要文件核对发布方校验和。

## 重启后任务没有被续传

- 确认任务在退出前**不是**被你手动暂停的：主动暂停的任务保持暂停，不会自动恢复。
- 确认队列没有被暂停、全局并发上限不为 0。
- 查看是否出现“启动恢复警告”：目标文件缺失、长度与记录不符，或被换成符号链接/目录时，恢复会拒绝写入并把任务标为失败，而不是冒险写坏文件。
- 远端内容已变化（`ETag`/总长度改变）时按设计整体重下，这在日志里会体现为一次重新探测。

## 删除任务失败或任务仍在列表里

- 勾选“同时删除文件”时，只有解析后仍位于默认保存目录之内的目标才允许删除；越界目标（含符号链接、`..` 逃逸）会让该选项不可用，此时只能删除记录。
- 停止下载或种子会话失败会中止整次删除，任务原样保留。稍后重试。
- 文件被其他程序占用时删除会失败。应用会保留任务并写入错误信息，关闭占用程序后重试即可。
- 未配置默认保存目录时无法校验删除边界，删除文件的选项不可用。

## 下载完成没有弹窗

- 确认“选项 → 常规 → 显示下载完成对话框”已开启。它与系统通知是两个独立开关：系统通知还需要操作系统的通知权限。
- 弹窗聚合所有未确认的完成条目，连发完成只弹一次；关闭弹窗即视为全部确认。
- 若条目显示“保存路径未知”，说明该任务已不在任务列表中，此时两个打开按钮都会被禁用——这是有意的，不是故障。

## 浏览器提示无法连接或 Native Host 不可用

1. 先启动 Multidown，再从扩展发送链接。
2. 确认扩展身份与[浏览器扩展指南](./browser-extension.md#固定身份)一致。
3. 确认 Host 清单名称为 `com.multidown.app`，`path` 是存在且可执行的绝对路径。
4. 确认清单安装在当前浏览器和当前用户读取的位置；Chrome 与 Chromium、Firefox 使用不同位置和授权字段。
5. **重新执行一次应用内的“安装浏览器扩展”**：Host 二进制是单独安装的，只升级应用不会升级它。升级应用后连接异常最常见的原因就是这个。
6. 重新加载扩展和浏览器；从源码构建时先运行 `npm run build:extension` 与 `npm run test:extension`。
7. 应用未运行时，扩展会请求系统打开 `multidown://open` 把它拉起来，最多等待约 5.4 秒。超时说明协议没有注册成功（安装器未注册 `multidown://`、或深链被系统拦截），此时先在浏览器里直接访问 `multidown://open` 看应用是否被拉起。
8. 若应用仍可打开，可暂用正确编码的 `multidown://add?url=...` 深链。

## 代理启用后全部连接失败

- 核对协议、主机、端口和凭据；HTTP 代理与 SOCKS5 不能混填。
- 临时选择“不使用代理”可帮助区分目标站点问题与代理问题。
- 系统代理模式依赖操作系统当前配置。
- TLS 证书错误不能通过关闭校验绕过；将组织 CA 正确安装到系统信任库。
- BT 专用 SOCKS5 代理会关闭 DHT 和本地发现，若 tracker 也不可达，可能找不到 peer。

## 代理配置莫名清空（代理都没了、代理规则消失）

“选项 → 代理服务器”里的代理和域名分流规则**已经永久丢失，应用内没有任何可回退的来源**。这与上一节的症状方向相反：上一节是配置写错了，改对即可；这里被销毁的是配置本身。

- 该文件不走其它状态文件使用的“临时文件 → 轮换备份 → 原子替换”，因此不会生成 `.bak` 备份链，也不会有 `.recovery-<时间戳>.json` 隔离文件。**你不会看到“启动恢复警告”**——这不是你漏看了提示，而是这条写入路径根本不产生恢复警告。
- 应用读到无法解析的内容时静默按“空配置”继续，所以界面上不会报错，只会表现为配置凭空消失。
- **密码必须重新输入。** 代理密码原本就保存在这个文件里，应用内没有第二份副本，也没有加密备份。
- 不要指望应用自行恢复，也不要手工编辑该文件去补回条目；此时能做的只有按记忆或你自己的记录重新配置一遍。
- 机制详见[已知限制](../reference/known-limitations.md#代理配置文件损坏会静默丢失全部配置)。该缺陷当前**尚未修复**，本页不给出修复承诺。
- 往后请按[数据保存在哪里](./getting-started.md#数据保存在哪里)的建议，在应用之外为代理配置单独留一份副本。
- 触发前提是写入过程中发生异常中断（进程被杀、断电、磁盘写满），不是正常操作就会发生。**如果你从未遇到过这类中断**，那么你看到的更可能是配置错误，请回到“代理启用后全部连接失败”核对协议、主机、端口和凭据。

## 磁力任务一直显示解析元数据中

- 等待活跃 peer 返回元数据；冷门或失效磁力链接可能永远没有结果。
- 检查 tracker、DHT 和防火墙；若配置 SOCKS5，DHT 会被主动关闭。
- 尝试使用同一资源的 `.torrent` 文件，以绕过磁力元数据发现。
- 确认系统时间和 DNS 正常，并重启应用使 BT 网络设置生效。

## 文件无法写入、移动或打开

- 确认保存目录存在、可写且空间充足。
- 避免选择系统保护目录、只读卷或已断开的网络盘。
- 目标文件被其他程序占用时，关闭占用程序后重试。
- “打开文件/所在目录”依赖系统关联；下载成功但无法打开不代表文件内容失败。

## 磁力链接或 torrent 双击没有打开应用

Multidown 只注册为候选应用。请在系统默认应用设置中明确选择它，或在“选项 → BitTorrent”使用关联按钮。最稳妥的替代入口是把 `.torrent` 拖入窗口。

## 仍未解决

查看[已知限制](../reference/known-limitations.md)和 [CHANGELOG](../../CHANGELOG.md)。提交公开 Issue 时提供可公开的最小复现信息；疑似安全问题必须遵循[安全策略](../../SECURITY.md)私下报告。
