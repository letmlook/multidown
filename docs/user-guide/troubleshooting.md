# 故障排查

先按症状定位，再收集版本、系统、任务地址类型和完整错误文本。日志或截图对排查很有帮助，但分享前应移除 Cookie、认证头、代理密码和个人路径。

## 应用无法启动或窗口空白

1. 确认安装包架构与系统一致。
2. Windows 检查 WebView2 Runtime；Linux 检查 WebKitGTK 等 Tauri 运行依赖。
3. macOS 检查“隐私与安全性”中的拦截提示。
4. 从终端启动应用以获取标准错误输出，但不要用管理员或 root 身份长期运行下载器。

## HTTP 任务探测失败

- 在浏览器中确认 URL 尚未过期，且不是需要网页脚本生成的一次性地址。
- 对登录资源补充正确的 Cookie、认证方式、Referer 或 User-Agent。
- 某些服务器拒绝 HEAD 请求或 Range 请求；重试后仍失败时，记录状态码和响应头。
- 检查系统时间、DNS、代理和防火墙。公司网络可能拦截未知客户端。

## 下载无法续传或重新从零开始

服务器可能不支持 Range，或远端文件的 `ETag` / `Last-Modified` 已变化。为避免拼接出损坏文件，Multidown 会在远端内容变化时整体重下。也应确认临时文件和目标目录仍可写、磁盘空间充足。

## 浏览器提示无法连接或 Native Host 不可用

1. 先启动 Multidown，再从扩展发送链接。
2. 确认扩展身份与[浏览器扩展指南](./browser-extension.md#固定身份)一致。
3. 确认 Host 清单名称为 `com.multidown.app`，`path` 是存在且可执行的绝对路径。
4. 确认清单安装在当前浏览器和当前用户读取的位置；Chrome 与 Chromium、Firefox 使用不同位置和授权字段。
5. 重新加载扩展和浏览器；从源码构建时先运行 `npm run build:extension` 与 `npm run test:extension`。
6. 若应用仍可打开，可暂用正确编码的 `multidown://add?url=...` 深链。

## 代理启用后全部连接失败

- 核对协议、主机、端口和凭据；HTTP 代理与 SOCKS5 不能混填。
- 临时选择“不使用代理”可帮助区分目标站点问题与代理问题。
- 系统代理模式依赖操作系统当前配置。
- TLS 证书错误不能通过关闭校验绕过；将组织 CA 正确安装到系统信任库。
- BT 专用 SOCKS5 代理会关闭 DHT 和本地发现，若 tracker 也不可达，可能找不到 peer。

## 磁力任务一直显示解析元数据中

- 等待活跃 peer 返回元数据；冷门或失效磁力链接可能永远没有结果。
- 检查 tracker、DHT 和防火墙；若配置 SOCKS5，DHT 会被主动关闭。
- 尝试使用同一资源的 `.torrent` 文件，以绕过磁力元数据发现。
- 确认系统时间和 DNS 正常，并重启应用使 BT 网络设置生效。

## 文件无法写入、移动或打开

- 确认保存目录存在、可写且空间充足。
- 避免选择系统保护目录、只读卷或已断开的网络盘。
- 目标文件被其他程序占用时，关闭占用程序后重试。
- “打开文件/所在目录”依赖系统关联；下载成功但无法打开不代表文件内容失败。

## 磁力链接或 torrent 双击没有打开应用

Multidown 只注册为候选应用。请在系统默认应用设置中明确选择它，或在“选项 → BitTorrent”使用关联按钮。最稳妥的替代入口是把 `.torrent` 拖入窗口。

## 仍未解决

查看[已知限制](../README.md#我负责发布维护)和 [CHANGELOG](../../CHANGELOG.md)。提交公开 Issue 时提供可公开的最小复现信息；疑似安全问题必须遵循[安全策略](../../SECURITY.md)私下报告。
