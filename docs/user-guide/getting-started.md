# 快速上手

## 创建 HTTP 下载

1. 点击工具栏的新建任务按钮，或从“任务”菜单打开新建任务。
2. 粘贴 `http://` 或 `https://` 地址。
3. 等待应用探测文件名、大小和断点续传能力。
4. 确认保存目录、文件名及可选的认证信息或请求头，然后开始下载。

预期结果：任务出现在列表中，并依次显示文件大小、进度、速度和预计剩余时间；完成后状态变为已完成，可从右键菜单打开文件或所在目录。

服务器不支持 Range 请求时，任务会退化为单连接下载。需要登录的资源可在任务对话框中提供 Basic/Bearer 认证、自定义请求头、Cookie 或 User-Agent。

## 管理任务

任务列表和右键菜单提供暂停、继续、取消、删除、失败后重试、重新下载、打开文件及打开所在目录等操作。

### 删除任务

删除任务时界面会先**预览将要处理的路径**，并把“同时删除文件”保持为**默认不勾选**：

- 不勾选时只移除任务记录，已下载的文件留在原处；
- 勾选时才会删除数据文件，并且只在目标位于你配置的默认保存目录之内时才允许勾选。指向目录外的路径（符号链接、`..` 之类的越界目标）会让该选项不可用，此时只能删除记录；
- 删除前应用会先停止该任务的下载或种子会话，文件句柄关闭之后才动文件。停止失败会中止整次删除，任务原样保留；
- 删除文件失败时任务**不会凭空消失**：它会被标为“失败”并带上错误信息留在列表里，便于你重试或改用手动删除。

### 完成后提醒

“选项 → 常规 → 显示下载完成对话框”打开时，任务完成后会弹出一个完成弹窗。这个弹窗把**所有尚未确认的完成条目聚合在同一个窗口里**，所以连续完成多个任务只会弹一次，不会刷屏，也不会漏掉其中任何一个。每条都有“打开文件”和“打开所在目录”。

如果该任务已经不在列表中，弹窗会显式标注“保存路径未知”并禁用两个按钮，而不是猜一个相对路径。

这个开关与“选项 → 通知与声音”里的“下载完成时显示系统通知”“下载失败时显示系统通知”是**互相独立**的：关掉系统通知不会关掉完成弹窗，反之亦然。系统通知还额外依赖操作系统的通知权限。

## 启动恢复

应用每次启动都会自动恢复上次未完成的任务，不需要手动操作：

- 上次处于活动状态的 HTTP 任务会按队列与并发上限重新开始续传，从持久化的区间状态继续，不是从零开始；
- 恢复前会核对区间状态、目标文件长度和远端身份（`ETag`/`Last-Modified`/总长度）。远端内容已变化时任务会整体重下，而不是把新旧内容混在一起；
- 目标文件缺失、长度不符，或目标已被换成符号链接/目录时，恢复会拒绝写入并把任务标为失败；
- 你主动暂停的任务保持暂停，不会被恢复成运行中；
- BitTorrent 会话与做种状态同样恢复，详见 [BitTorrent 指南](./bittorrent.md)。

### 启动恢复警告

如果某些下载记录无法恢复，界面顶部会出现“启动恢复警告”，逐条给出出问题的范围（任务、队列、规则等）、具体原因，以及**原始数据被保留到的隔离文件路径**。这表示“数据已保留、线索在这里”，不是“数据丢失”。

- 隔离文件与状态文件在同一个应用数据目录内，文件名形如 `<存储名>.recovery-<时间戳>.json`，可以自行打开检查；
- 点“忽略”只表示**本次会话不再提示**：应用只清理界面上的提示列表，**不会删除也不会修改磁盘上的隔离文件与备份**。想找回原始记录时请直接去应用数据目录；
- 重新启动应用时这些警告会再次出现。

## 其他添加方式

- 从剪贴板添加单个或批量 HTTP(S) 地址。
- 粘贴磁力链接、选择或拖入 `.torrent` 文件，详见 [BitTorrent 指南](./bittorrent.md)。
- 通过浏览器右键菜单或下载接管发送链接，详见[浏览器扩展指南](./browser-extension.md)。
- 使用 `multidown://add?url=...` 深链；URL 参数必须正确编码。

## 队列、批次与计划任务

- 队列用于限制一组任务的并发数和执行顺序；全局并发上限与队列上限会共同生效，暂停的队列不会启动新任务；
- 批次用于一次导入多条 URL、统一命名和查看聚合进度；
- 分类规则可按扩展名或域名选择保存目录；
- 定时调度支持开始下载、暂停全部、继续全部以及临时限速。

这些行为可在“选项”的队列、批次、分类规则和定时调度页面管理。常用设置见[设置说明](./settings.md)。

## 导入与导出

任务菜单支持将任务列表导出为 JSON，或从兼容的 JSON 文件导入。导入前请检查其中的 URL 和本地路径；导入任务不会自动搬移已有文件。

## 数据保存在哪里

任务、设置、队列、批次、分类规则、定时规则和代理配置都保存在系统的应用数据目录中，文件清单见[平台路径](../reference/platform-paths.md#应用数据)。写入采用“临时文件 → 轮换备份 → 原子替换”，因此异常退出只会留下完整的新文件或完整的旧文件；同目录还保留 `.bak` 备份链。

需要注意：**Windows 上存在一个尚未定位的偶发写入失败**（`os error 5` / `os error 32`），偶尔会导致任务列表没有保存成功。表现与应对见[已知限制](../reference/known-limitations.md#安全与可靠性边界)。
